# 实施路线与验收

本路线将 v0.4 设计分为可独立验证的交付批次。模块设计已补齐不表示其接口已经运行；最初设计基线为 37 项 Rust 测试。后续已完成独立路由/投递调度、有界数据库接纳、HTTP 缓冲优化，以及容量/磁盘保护、失败路由隔离和 v1→v2 迁移；P1 基线为 76 项回归测试通过，另有 1 项手工性能测量。P0 已实现人工证据核查、授权恢复、目标调度和指标；自动渠道核查与分布式路由租约尚未完成，详见[本阶段实现](backpressure.md)。

P1 已落实内容引用、流式 HTTP、数据库公平优先级、历史保留、备份恢复、配置快照与原子来源游标；范围和剩余边界见 [P1 实现](p1-storage.md)。R1–R5 的完整业务闭环尚未因此完成。

本阶段已完成 R1/R2 的最小 HTTP 工具路径，并增加外部 OAuth introspection、资源发现、独立管理认证与在线暴露发布。首期管理台已接通能力编辑、发布结果核查与历史查询，浏览器主流程已在临时库验收。此前管理台阶段已有 116 项 Rust 测试与 7 项前端测试通过；Keycloak 本地联调已通过；公网客户端验证、动态 grant 管理、上游桥接和 Runner 仍待完成。见[OAuth 接入与在线配置发布](oauth-publication.md)。

本轮完整回归为 123 项 Rust 测试通过，1 项手工基准默认忽略；前端本轮未改动。最新增量为签名 webhook、普通 JSON 接入、内容指纹去重，以及 MCP 资源、资源模板、提示词和补全。参见[本轮能力与限制](../webhook-mcp.md)。这些能力不代表上游桥接、主动 Agent 唤醒或消息原路回复已经完成。

已进一步实现 R3 的 JSON/HTTP 来源闭环：Webhook → 持久化任务 → MCP 领取/分析结果提交 → 来源适配器回调。129 项 Rust 测试通过，另有 1 项手工基准忽略。模型推理、自动轮询 Worker、原生聊天渠道与事件推送不在本批次，详见[实现边界](../agent-inbox.md)。

## R0 可靠调度和迁移基础

覆盖事件、路由、投递、存储、审计模块。新增 RoutingTask、DeliveryAttempt、due_at/错误阶段、独立 worker 池、有界数据库 admission 和只读状态查询。先完成旧库迁移框架，再为未路由事件幂等回填任务。

验收：最早 100 条永久失败事件不阻塞后续事件；慢 HTTP 目标不阻塞路由；重启不会再次发送已完成记录；过期 Sending 保留核查；并发与磁盘压力下不无界排队；迁移前后事件 ID、去重标记和目标不变。增加可授权的核查与显式重放用例，不直接提供任意 SQL 修复入口。

## R1 配置控制面和身份基础

覆盖配置、能力、身份、凭据、管理 API。实现 Connection/Destination/RouteSet revisions、配置导入预览、发布事务与运行激活状态。提供真实 ProfileRepository、SchemaValidator 和当前授权查询；秘密先支持环境引用，再接加密 Vault。OIDC 登录与 MCP 资源服务器认证原型分开验收，沿用外部成熟授权服务方案。

验收：静态链路可导入为初始 Release；并发编辑冲突可见；配置变更不换旧任务目标；授权撤销与密钥轮换行为可追踪；缺少 PerUser 上游授权不回退共享账号；导入默认草稿且不立即发送。

## R2 MCP 工具和调用账本

覆盖能力发布、MCP、Invocation 与管理台。先接一个 HTTP 工具和一个真实客户端，实现目录过滤、公开别名、工具调用和 InvocationStore，再接两个上游 MCP 服务器验证同名冲突。资源与 Prompt 依据实际需求逐项接入并验收。

验收：授权用户可调用选定工具；隐藏工具直调、原始资源 URI 绕过被拒绝；同键异参拒绝；结果保存/审计失败不会诱发重复写调用；上游 Schema 变化不会自动扩大已发布权限。协议版本及 SDK 版本以原型结果记录，事件能力另作兼容条目。

## R3 Agent 分析和原路回复

覆盖 Agent、会话、内容、路由、投递和 MCP。实现 AgentBinding、Inbox、AnalysisJob、消息/路线存储、ReplyPlanner 与 AnalysisCommitter。选择一个已验证可收发的渠道，以及外部 Agent Worker；可先用本地测试渠道验收事务，再接平台驱动。

验收：收到消息 → 创建任务 → Agent 领取 → 结果提交 → 原会话回复完整运行；租约过期/结果重交不产生重复回复；无事件能力的客户端显示等待领取；回复失败与分析成功分开；附件及会话上下文不跨授权范围。策略要求审批的结果停在待审意图，其余已授权结果可自动回复。

## R4 连接器运行与扩展来源

覆盖工厂、Supervisor、Checkpoint、Runner。用 MQTT 流订阅和 RSS/Atom 轮询验证不同来源模式，再接受控 CLI 工具执行及持续输出来源。跨语言 SDK 用受管进程协议适配，远程节点在本地契约成熟后加入。

验收：来源重连和 retained/历史导入语义明确；Checkpoint 旧 generation 被拒绝；慢消费者有界背压；配置停用不会被重连复活；CLI 超时能回收进程树且不越权；远程节点断连不会盲重跑写操作。

## R5 管理体验与运行交付

补全连接向导、能力选择/差异、发布状态、消息链路、核查与重放、指标、保留策略、备份恢复、配置导入导出及 SDK。增加至少一种真实消息发送渠道和一种双向聊天渠道，分别记录能力与版本验证结果。

验收：从空库按文档完成连接、发布、调用、事件转发与故障恢复；备份恢复演练保留幂等窗口；命令行和管理台使用同一服务端权限；文档与实际 API 状态一致。PostgreSQL、多实例及更多平台以真实负载和渠道需求决定，不作为首个闭环的前置条件。

## 架构验收清单

每个模块具备职责、实体与数据归属、端口、状态/事务、依赖和失败恢复及测试门槛。跨模块检查：每个异步成功回执能定位提交事实；每个副作用有执行记录；每个状态有唯一所有者；每个消费位置有确认顺序；每个公开引用有读取权限；每个自动重试有可证明的重放前提。

新增模块不通过简单的 allow-all、内存持久化替身或 Unsupported 占位来宣称完成；真实实现与测试替身分开。基于 shared contract suite 验证不同存储和适配器，而不要求所有连接器支持同一组功能。

## 尚待实施阶段冻结的选择

Keycloak 已作为首个参考授权服务并通过本地联调；生产部署方式、MCP 客户端兼容矩阵、首个双向聊天平台、正文/幂等保留期、部署容量、Windows Runner 优先级、开源许可证。它们不阻塞本次模块契约；在相应交付前形成 ADR 和可复现验证，架构设计不替代平台权限与兼容测试。
