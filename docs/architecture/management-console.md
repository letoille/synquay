# Synquay 管理台设计

设计基线，2026-10-25。管理台面向连接程序、发布 MCP 能力、转发消息和排查运行问题的管理员。设计目标：**简洁、易用、正式、克制**。本文确定信息架构、关键流程和实现边界；交互草图中的连接、消息和发布记录均为示例数据。

首次接入向导、在线新增 HTTP 能力与能力编辑发布管理台已实现，运行方式及实际验收见[管理台运行说明](../management-console.md)。其他协议连接、消息规则和运行记录仍按本文分期推进。当前界面使用顶部导航，默认进入“MCP 服务”；MCP 服务同时提供独立顶部入口与连接列表入口，两者进入同一配置页面。路由和运行记录的在线管理尚未开放，不展示不可用菜单。

## 产品组织

管理台围绕“连接”和“路由”组织。入口、出口是连接在一次交互中的角色，同一连接可以同时接收、发送或提供调用能力。MCP Server 是面向 Agent 的特殊连接，不是所有消息的必经处理中心。为方便配置开放范围和客户端接入，界面另设 MCP 服务顶部入口，不创建第二份配置。协议适配、路由、任务、投递的后端职责仍然独立，不因界面概念合并而混用状态机。

采用顶部导航，不设置固定侧边栏，也不设置独立工作台。目标结构为“MCP 服务、连接、路由”，运行记录作为次要入口；设置、语言与主题位于右侧。首版单工作空间只显示名称，不提供无意义的空间切换器。

| 入口 | 用户要解决的问题 | 主要内容及实现状态 |
|---|---|---|
| 连接 | 接入什么、可以做什么 | 已接通 HTTP 能力配置与本机 MCP 连接；其他协议按实际驱动能力开放 |
| MCP 服务 / 连接 → Agent 连接（MCP） | 向 Agent 开放什么、如何接入 | 能力、接入方式、发布历史；保留已接通的发布和恢复流程 |
| 路由（规划） | 消息从哪里来、到哪里去 | 来源、条件、映射、直接转发或创建 Agent 任务、结果去向 |
| 运行记录（规划） | 这次交互到哪一步 | 调用、路由、任务、每个投递分支的时间线 |
| 设置（规划） | 谁能使用、系统如何运行 | 完整身份认证、凭据引用、审计、容量与保留策略 |

连接清单按实际能力标识“接收、发送、调用”，不凭协议名称推断可用操作。现有 HTTP 端点只标为可调用；MCP 连接标明接收调用与返回结果。MCP 的任务领取、结果提交、事件通知依赖已发布能力与客户端支持，不能把双向协议等同于可靠消息推送。

MCP 详情保持 Profile 发布范围、调用方授权和消息任务访问范围的区分。Profile ID 默认收起；任务和回复目标的授权不会因选择一个 MCP 连接自动扩大。上游 MCP 桥接与对外 MCP 服务在连接类型中区分方向，协议实现仍分别管理。

## 让用户直接理解如何配置

连接页首先说明“连接决定接入什么，路由决定消息去哪里”。配置指引直接嵌入页面，不再先经过一个介绍首页。当前可用路径分为“添加软件或设备 → 配置 MCP 连接 → 在 Agent 中接入”。已有能力和已发布范围决定下一步按钮；不根据已发布就宣称外部 Agent 已连接或已通过验证。

“只转发消息，或交给 Agent 处理？”展开说明两种路径：

- 入口连接 → 路由 → 出口连接：例如 Webhook 告警转发到邮件，不需要 MCP。
- 入口连接 → 任务 → MCP 连接 ↔ Agent → 结果投递：经领取和提交后，按规则返回原会话或指定目标。

路由在线配置未实现时明确标注，不放模拟启用开关或伪造运行记录。后续实现路由时，先选来源和目标，按需展开匹配、映射、Agent 任务与结果处理。可同时添加直接转发和 Agent 处理分支，独立显示各目标状态。规则是关联的单一配置来源，连接详情仅显示引用与跳转，避免重复维护。

## 页面和交互约定

- 页面采用顶部导航、标题与简短说明、局部操作区、主要内容四层结构。每个任务区域只有一个主按钮。
- 列表使用名称、类型、状态、最近结果等必要列。详情用独立页；短信息可展开在当前行下。复杂配置不塞入多层弹窗。
- 只有一组对象时直接进入详情；有多组时进入列表。搜索、分页和过滤随真实数据规模启用。
- 高级字段默认收起。显示人能理解的名称，技术 ID、原始 Schema 和追踪标识放在详情中。
- 保存草稿不影响运行版本；发布才激活。页面持续标明已发布版本、草稿状态、待发布差异。
- 离开未保存编辑时提供保留、舍弃和继续编辑。成功反馈在原操作附近呈现，错误保留输入并指出下一步。
- 一般查询和安全编辑不重复确认。外部副作用、覆盖、重放等使用包含对象、影响和版本的具体预览。

## 四个核心流程

### 接入程序

选择类型 → 填写名称与必要参数 → 绑定凭据引用 → 校验配置 → 可选连接测试 → 保存草稿 → 发布启用。

表单随连接器配置 Schema 展示。先提供必填项，再展开超时、并发、订阅 QoS、重连、速率等高级设置。只允许选择服务端已安装的类型和已授权执行环境；CLI 以受控命令配置为基础，不提供任意远程终端。

连接测试应说明测试范围；只有适配器明确声明无业务副作用的检查才能作为普通测试。调用写工具或发送测试消息需要明确显示目标和内容。保存配置不会顺带执行工具。

成功后展示下一步“发布能力”或“创建消息规则”。暂停、断开、凭据失效、限流、重连中分别标识；暂停订阅不能笼统描述为取消所有正在执行的任务。

### 发布给 AI 使用

选择服务 → 勾选能力 → 保存草稿 → 预览差异 → 发布 → 查看回执。

能力表显示友好名称、来源、类型及副作用信息。副作用未知时标为“未声明”，不能默认标为只读。详细 Schema 按需展开。新发现的上游能力默认不勾选；新增能力不会绕过管理员发布。

预览显示新增、移除、保持不变的能力，以及能够可靠计算的受影响客户端。尚不能计算影响时直接显示“影响范围尚不可计算”，不虚构为零。发布等待在途调用时展示“等待当前调用完成”，允许离开后根据操作 ID 恢复查询。

服务可见范围与调用者授权共同决定最终可调用内容。查看某个调用者的权限需要服务端计算，前端不自行推导权限结论。当前文件管理的授权在界面中标为只读，并提供配置位置说明。

接入方式提供实际 MCP 地址、认证方式、连接检查结果和客户端配置说明。管理台登录与 Agent 的 OAuth 授权是两条独立流程。取消发布不能被描述成撤销已发出的所有令牌；客户端刷新目录的时机应按实际行为说明。

### 转发与 AI 原路回复

创建规则采用顺序表单：来源 → 筛选条件 → 处理方式 → 目标。初期不做拖拽画布。

直接转发：选择一个或多个渠道，配置必要字段映射，预览目标和脱敏后的消息。AI 分析：选择允许领取任务的 Agent、任务模板、超时及失败策略，再选择原路回复或指定渠道。

规则测试默认只匹配、转换和预览，不发送真实消息。真实试投递另行展示明确操作。避免同一消息在两个连接间循环转发，显示来源保留、跳数上限和重复抑制的配置结果。

AI 返回结果与回复投递分别显示状态。没有 Agent 领取时显示等待领取；不能承诺仅通过 MCP 通知就自动唤醒任意 AI 平台。原路回复缺少会话映射时展示阻塞原因，不能静默改发其他渠道。

### 查找和处理异常

从连接、路由的异常摘要或运行记录进入运行详情，保留来源筛选和返回位置。详情展示接收、路由、分析、回复、投递的关联时间线；并行分支和各个目标分别有状态，避免一条失败把其他成功隐藏。

摘要先给结果、对象、时间和下一步；尝试次数、配置版本、脱敏错误、request_id 等位于详情。大消息只显示摘要和长度，附件按授权流式下载，不一次性塞入浏览器或日志。

“结果未知”使用独立状态并优先提供“核查结果”；不能等同于失败或提供默认立即重发。人工重放预览目标、内容、配置版本与重复风险，记录原因并创建关联的新执行；重试沿用已有逻辑操作身份。

## 视觉语言

| 项目 | 设计约定 |
|---|---|
| 颜色 | 中性色作为页面和导航背景；低饱和蓝色用于必要强调；红色只用于错误或破坏操作，状态始终配文字 |
| 字体 | 系统字体，正文 14px、辅助文字 12px、页面标题 22–24px；少用粗体，数字列等宽对齐 |
| 留白 | 4px 基础单位，主要分组间距 24px，表格默认行高约 56px，可切换紧凑密度 |
| 形状 | 6–8px 圆角、细分隔线；普通页面不用装饰阴影、渐变、嵌套卡片和大面积彩色块 |
| 操作 | 主按钮实色，次按钮描边或文字；标签明确表示“保存草稿”“预览发布”等实际动作 |
| 反馈 | 轻量就地反馈；重要异常有明确下一步。加载、无数据、无权限、失联分别设计 |
| 响应式 | 桌面顶部导航；窄屏导航移至品牌与外观控件下方，表格转信息行，保留名称、状态与主要操作，不只缩小字号 |
| 无障碍 | 原生表单、可见焦点、标签与错误关联、键盘可操作，触摸目标至少约 44px；深浅主题均检查对比度 |

不使用营销首页式大标题，不用没有操作意义的总量数字填充概览。页面第一次使用时以一个明确的下一步代替空表格和大量灰色占位菜单。

## 关键状态及恢复

| 状态 | 页面行为 |
|---|---|
| 首次使用 | 默认进入连接页，展示可完成的配置步骤及“添加连接”操作 |
| 未保存 / 草稿已保存 | 明确区分本地编辑与服务端持久化草稿，显示是否影响当前服务 |
| 发布中 | 展示 operation_id 对应进度，不重复提交新操作 |
| 请求超时、结果未确认 | 保留原 operation_id，重新查询或按契约安全重试；不能直接显示发布失败 |
| 版本冲突 | 显示服务端新版本与本地修改，允许重新基于最新版本编辑，不静默覆盖 |
| 授权失效 | 停止写操作，重新认证后重新读取版本；不自动提交旧表单 |
| 数据暂时不可用 | 标明最后刷新时间，保留已有数据但提示陈旧；状态查询不制造成功结果 |
| 限流或积压 | 显示受影响目标、等待时间或容量原因，给出降速/恢复入口；未知数值不估造 |
| 无管理权限 | 可保留授权允许的只读视图；服务端仍拒绝越权请求 |

## 前后端边界

前端继续使用现有 React + Vite 工程。按用户功能划分 `features/connections`、`mcp-services`、`message-rules`、`runs`、`settings`；`app` 管路由、会话和布局，`shared` 放基础控件与类型化客户端。各功能分别组织页面、表单、查询和命令状态，不把所有 API 与状态放进 App.tsx。

服务端状态、未保存表单、视图过滤分别管理；查询键包含授权上下文和对象版本。切换身份清理缓存。列表游标分页，详情分段加载；仅可见的活动任务进行有上限、退避的刷新，离开页面取消请求。事件流只提示重新查询，持久化回执是完成依据。

管理查询聚合已有模块的读模型；写请求调用拥有该状态的应用用例。所有授权、版本校验和幂等约束在服务端落实。发布记录、运行时间线和权限预览都需要正式查询契约，不能从日志文本拼凑。

当前按用户要求移除管理台登录与管理员令牌校验，保留来源防护、资源限额及审计。MCP 与业务接口认证独立保留。正式部署优先独立管理员登录与服务端会话，使用 HttpOnly/Secure/SameSite Cookie、CSRF 校验和允许来源校验。现有 Keycloak Agent 授权验证不代表管理台登录已经实现。

## 分期范围

| 阶段 | 管理台交付 | 后端依赖 |
|---|---|---|
| 第一阶段 | MCP 服务能力选择、草稿、差异预览、发布回执、接入说明、发布历史 | 复用 config/draft/publish API；补浏览器来源策略、操作状态与历史查询、安全错误契约 |
| 第二阶段 | 运行记录、异常详情、受保护恢复、连接实例只读详情 | 补分页读模型和时间线查询；复用现有调用账本、Outbox、恢复用例 |
| 第三阶段 | 连接向导、消息规则、Agent 分析和原路回复管理 | 连接器实例管理、动态路由、AgentInbox 等目标模块完成后再开放 |
| 后续 | 多发布方案、上游桥接、细粒度管理员角色、动态授权及更多能力类型 | 以相应服务端能力为前提，单独补验收 |

第一阶段实际导航只出现可用内容；完整设计中的规划入口仅在设计预览展示。首版不提供伪造运行数据、不可用的“连接测试”或未实现的授权编辑。

## 验收标准

1. 用户能清楚区分连接配置、MCP 暴露范围和消息规则；每条主流程不需要先理解后端模块名称。
2. 勾选能力不会立即改变运行服务；预览与最终发布基于同一草稿版本，冲突可恢复。
3. 超时后能够找到原操作结果，不重复发布或投递；结果未知与已失败呈现不同下一步。
4. 从一条消息能追溯分析结果和每个投递目标，且不会把 AI 完成误认为已经回复用户。
5. 未授权能力、秘密和原始敏感内容不会因详情、导出或错误反馈泄露。
6. 键盘可完成主流程；320px 宽度和深浅主题下没有主要操作被遮挡。
7. 空态、加载、无权限、失联、版本冲突均有明确反馈；正式界面仅展示已经接通的真实功能。

## 多 MCP 服务与连接端点（2026-10-25）

MCP 服务位于连接前面，页面直接展示服务清单和创建操作。卡片首行显示名称、地址、客户端统计位置，第二行显示用途说明与工具名称，以及非零的资源/提示词数量，右侧为启用/停止、编辑、删除图标。当前无状态 HTTP 不保留客户端会话，显示“客户端 0”，不是近期调用者统计。默认旧 `/mcp` 服务自动登记；新建服务默认使用 8 位随机路径，可修改公开 URL。保存同步更新实际路由，旧路径失效，路径在工作空间内唯一。删除保留审计和底层连接，重启不恢复已删除服务。

每个服务使用独立 Profile 和版本，并保存各自的资源、资源模板和提示词范围；默认服务继续提供任务收件箱。每个服务可以配置 Basic Auth、JWT（RS256）、OAuth 或无鉴权。旧部署认证仅作为兼容状态保留。认证绑定服务 ID 和配置版本，开放工具和空间授权共同约束调用；服务管理与旧能力发布共享发布锁。

连接的多协议、多入口、多出口方案见 [连接、入口与出口配置](connections-and-endpoints.md)。HTTP 接收、HTTP 主动请求、MQTT 订阅与发布按真实角色配置，不建立互斥的“输入连接/输出连接”类型。

## 连接收发与路由交互（2026-10-25 设计决策）

连接是可复用端点，接收和发送是它的能力；来源和目标是端点在某条路由中的角色。不要把连接永久划分为入口/出口，也不要把所有流量都画成经过 MCP 的链路。Agent 是处理者，MCP 服务是其接入接口，二者不能在可执行配置中混用。以下路由界面是设计方案，尚未实现；当前在线连接配置仍是 HTTP 工具调用。

### 页面分工

顶部导航保留 MCP 服务、连接，并在路由管理 API 可用时增加路由。连接页配置协议端点、接收/发送操作和认证；路由页配置消息如何在这些能力之间传递；MCP 页选择向 Agent 开放的工具、资源、提示词。连接卡片显示名称、协议与用途、地址，第二行说明；HTTP 主动调用标为“HTTP · 发送”。后续双向连接分别列出接收与发送配置：MQTT 的订阅和发布 Topic 不共用一个含义不清的字段。

### 路由列表作为默认视图

采用路径卡片，第一行名称、状态，右侧启停/编辑/删除。主体明确显示“来源 → 可选处理 → 目标”；目标超过一个时采用分支，最多展开三个，其余用“+N 个目标”。底部只显示有事实依据的最近结果和时间，异常时优先显示失败或积压，不以“已启用”冒充“运行正常”。协议、能力名称使用轻量标签；完整 URL、Topic、凭据配置在节点详情中查看。

例：

- 订单通知：订单 Webhook（接收）→ 业务 HTTP（发送）
- 设备控制：微信（接收）→ 指令 Agent（处理）→ 家庭 MQTT（发布）
- 日常问答：微信（接收）→ 问答 Agent（处理）→ 回复来源
- 设备告警：家庭 MQTT（订阅）→ 告警 Agent（处理）→ 微信（发送）、邮箱（发送）

列表支持按连接、是否经过 Agent、启用/停用、异常筛选。全局关系图是辅助视图，按实际节点及方向自动布局，不固定为三角形；点击连线进入相应路由，点击节点查看关联路由。不要把自由拖拽画布作为创建第一条路由的前置操作。

### 创建和编辑

使用足够宽的编辑面板，主区为三个纵向区块，上方路径摘要随选择实时变化：

1. 来源：选择连接，然后选择它支持的接收操作。候选项展示用途；只显示真正支持接收的操作。MQTT 订阅 Topic、Webhook 接收端点属于该接收操作。
2. 处理：默认直接转发；可选过滤、字段映射，或交给 Agent。基础流程展开，重试、超时、限流、失败处理等低频选项折叠。只有真实支持主动调用/领取任务的 Agent 才能选择相应处理模式。
3. 目标：选择连接与发送操作，可增加目标；Agent 场景可选择“回复来源”，但必须存在可用的回复通道。各目标单独配置消息内容和字段映射，显示一个真实样例的预览。

节点选择器按可用能力筛选，并提供“添加连接”；添加完成后返回路由草稿并自动选中。缺少目标、方向不支持、数据结构不匹配时就地指出问题。未实现的协议和投递模式不作为可保存选项。测试分为“不发送的映射预览”和明确标注的“实际试发”，避免预览产生外部动作。路由初次保存默认停用，验证配置后可直接启用。

### 三种往返关系

- 单向转发：一条方向明确的规则。
- 双向独立转发：两条规则，可在界面中分组为一个卡片，分别显示两个方向与启停状态。“添加反向路由”只预选交换后的连接，接收/发送操作、Topic、过滤和转换需独立核对，不能直接交换字符串后启用。
- 请求与回复：不是两条通用转发规则。HTTP 调用的响应走原请求；Agent 的“回复来源”使用可信来源生成的会话/消息关联信息，关联本次任务与回复目标。消息内容不能覆盖回复地址。Webhook 已响应后不能自动向原 HTTP 请求追加回复；异步结果必须使用已配置回调、其他发送能力或结果查询。

同一 MQTT Broker 或聊天机器人可能在多条路由中同时出现为来源和目标。以连接 ID + 操作 ID 绑定，不依赖展示名称。方向箭头、协议标签、文字状态共同表达含义，不仅依赖颜色。

### 运行状态与防回环

Agent 路径至少区分等待领取、处理中、结果待投递、成功、失败/超时；MCP 连接存在不代表 Agent 会自动醒来。卡片显示“等待 Agent”而不是“发送成功”。运行详情串联接收、路由命中、处理、分支投递和回复记录；失败重试以具体投递为单位，不默认重跑 Agent 或已成功分支。

双向规则需要传播消息 ID、因果关联和路径，限制跳数，并在入口按业务 ID 或适配器回声标识去重。外部系统可能丢失这些标识，不能声称仅靠内部 ID 就能消除全部循环；应在反向配置中展示消息类型/Topic 过滤及防回声设置。支持接收自己发出消息的适配器默认过滤可识别回声。

### 当前连接修改/删除实现

HTTP 连接卡片提供编辑和删除。编辑保存可修改公开名称、说明、URL、操作性质、输入 Schema 和本机 HTTP 许可，保留连接 ID、内部工具 ID、原有认证引用、输出 Schema 和文档。已有 OAuth 命名授权的重命名须先调整部署授权，防止无意转移授权。

删除确认说明会清除全部 MCP 发布工具引用及持久化草稿引用，保留 MCP 服务与历史审计。删除和更新同步所有引用该连接的发布版本，包括停用服务。整批版本、草稿审计、当前覆盖记录及操作回执在一个 SQLite 事务中提交；调用与发布通过同一 gate 协调。旧版本调用和旧草稿不能恢复被删除项。数据库 v14 为当前覆盖/删除标记及独立回执建表，使用作用域复合主键和有效记录部分索引；删除标记覆盖文件配置，重启不复活。未进入此管理模型的静态 pipeline 路由不会被声称自动修改；未来路由管理必须接入同一引用清理事务。


### 第一阶段实现边界（2026-10-25）

路径卡片、三段式编辑、事件类型筛选、多目标、关系图、启停删除和真实投递计数已实现。运行模型为 `ManagedRoute → RouteTarget → RouteRule`：一个用户路径包含多个稳定分支，分支进入原有 RoutingService 与 outbox；配置快照在分发锁内持久化并切换，保留原有背压、去重和发送调度。

这一阶段只管理部署拥有的 Webhook/HTTP 端点，不扩展任意网络地址或凭据权限。新路由默认停用；文件中的既有路径首次迁移保留启用状态。MCP 工具连接目录与 pipeline 目录尚未统一，工具删除不会改变 pipeline 端点。后续统一 Endpoint/Operation 目录后，才能开放在线适配器创建、引用级联清理、MQTT 双向及 Agent 回复配置，不能让前端先提供不可运行的选择。详情与验证见 `../management-console.md`。
