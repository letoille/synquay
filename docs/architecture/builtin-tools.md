# MCP 内置工具设计

2026-10-28。内置只读工具、MCP 发布与服务级授权界面已接入。默认不开放；近期消息目前仅覆盖已接收的 QQ 文本。

## 定位与目录

内置工具由 Synquay 提供，与连接定义的设备操作并列，通过 MCP Server 独立选择发布。默认全部关闭。下列工具按 MCP 服务分别启用：

| 工具 | 输入 | 返回 |
| --- | --- | --- |
| `synquay_builtin_connections_list` | 无 | 有权查看的连接 ID、名称和类型 |
| `synquay_builtin_connection_status` | 一个连接 ID | 启用状态、运行状态、来源和观察时间 |
| `synquay_builtin_connection_statistics` | 一个连接 ID | 接收和发送累计计数、明确计数口径 |
| `synquay_builtin_recent_messages` | 连接 ID、会话类型和 ID、游标、数量 | 已授权会话中的近期文本及缓存覆盖说明 |

工具是只读的；不开放修改连接、发送消息、删除数据、执行命令或访问凭据。固定工具 Schema 限制输入长度、分页大小、响应大小和非法参数。返回必须是结构化数据，不能返回连接配置中凭据、内部路径、签名或上游原始响应。

## 授权范围

每个 MCP Server 保存独立的内置工具集合及连接范围；消息正文额外限定连接、机器人账号、会话类型和会话 ID。默认空范围、默认不发布。连接列表和查询均只能看到其授权范围，未经授权的资源不透露名称、计数或是否存在。读取前在服务端使用当前身份、工作区状态、MCP 服务状态、发布版本、客户端授权、连接状态及会话范围做交集校验，不能以客户端传入的 ID 或消息正文作为授权依据。OAuth 客户端授权不能因启用工具而自动扩大。

连接删除、停用、账号更换、会话范围或服务授权撤销后，立即拒绝后续查询；失效的发布快照、旧游标和未完成调用不能恢复已撤销的范围。对连接和会话的授权修改需要 CAS 和持久化审计，与工具发布保持一致。

## 消息正文的执行边界

现有通用工具调用账本会持久化 `SavedOutcome`，因此不能直接通过该调用路径返回消息正文，否则会额外留下持久化副本。经明确标记的内置只读查询使用不持久化输出的执行路径：先授权并记录不含正文的开始审计，执行前复查授权，返回前复查授权并完成不含正文的审计，任何审计失败不能放行正文。失败只返回安全错误码。不得以可变权限为前提缓存并重放旧正文。

该路径仅用于明确声明的无副作用只读操作；普通设备控制、发送消息等继续使用原有持久调用账本、幂等与结果核查。消息读取不承诺同一调用 ID 返回相同正文；游标需绑定会话、授权范围及缓存生命周期，重启后安全拒绝旧游标。

## 状态与消息语义

连接启用与实际连接状态分开；MQTT 显示真实运行时状态，HTTP Client 显示按需调用；无观察数据时返回未知及原因，不推断在线。接收计数表示入口接受，发送计数按对应连接驱动的接受口径，均不等于最终设备执行或聊天对象已读。时间及计数器来源必须明确。

近期消息来自有界内存缓存，当前只覆盖已验签且持久化成功的 QQ 文本。返回保留范围、数据是否可能缺失、接收时间与 `history_complete=false`；不泄露附件 URL，不表示平台完整历史，也不表示能主动唤醒 MCP 客户端。跨进程或跨数据库的部署需显式处理共享关系；MCP 与消息管线不在同一工作区及数据源时应拒绝提供这些工具，而不是返回错误连接的数据。

## 管理台与验证

MCP 服务编辑界面将内置工具单独分组，并配置允许的连接；勾选消息查询时还必须选择具体已发现的群/单聊。保存使用现有服务版本校验，编辑、停用、删除不意外恢复权限。MCP 工具目录展示用途、参数和只读属性。当前无鉴权 MCP 服务若开放消息正文，界面须清楚显示其公开范围。

验收：多 MCP 服务和 OAuth 客户端隔离；禁止跨工作区、连接、账号、群和单聊读取；未授权对象不泄露存在性；撤销后旧服务/游标不能读取；连接变更立即生效；进程重启、缓存过期、淘汰、并发插入时分页行为明确；消息正文不进入日志、审计或调用账本；未启用时 MCP 列表和调用均不可见；验证状态与发送计数不夸大实际交付。
