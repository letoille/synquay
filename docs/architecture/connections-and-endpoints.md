# 连接、入口与出口配置

2026-10-26 更新。本文保留完整端点架构目标；已落地范围为 Webhook、HTTP Client、MQTT Client 的在线连接配置和消息路由，详细契约见 [消息连接](../message-connections.md)。当前每个 MQTT 连接支持一个订阅过滤器与一个发布 Topic，多端点集合仍是后续扩展。

## 核心关系

连接是一份可复用的传输与身份配置，入口、出口是连接中的具体能力。一个连接可以有多个接收入口、发送出口和可调用操作；不把连接标为互斥的“仅输入”或“仅输出”。路由引用 `workspace_id + connection_id + endpoint_id + revision`，不能只引用一个模糊的连接名称。

MCP Server 仍是连接，但因发布与客户端接入的操作频率，管理台在顶部单独提供“MCP 服务”。用户看到的导航是 MCP 服务、连接，路由与运行记录在真实接口开放后加入。MCP 服务使用底层连接的能力引用，不复制连接、凭据或执行器。

## 类型与能力

| 连接类型 | 接收入口 | 发送出口 | 可调用操作 | 配置重点 |
|---|---|---|---|---|
| HTTP Server / Webhook | 接收指定路径、方法和格式的请求 | 请求内回执不是通用消息出口 | 按适配器声明 | 路径由平台分配、签名或认证、大小限制、幂等键、接收回执 |
| HTTP Client | 可选定时拉取，属于独立的来源能力 | 向指定 URL 主动请求 | 由请求与响应契约定义 | Base URL、受限路径、方法、凭据引用、请求映射、响应判定、超时与幂等 |
| MQTT | 一个或多个 Topic Filter 订阅 | 向具体 Topic 发布 | 有参数契约的发布指令，可选择设备回执 | Broker、TLS、凭据、Client ID、会话、每入口/出口的 QoS、Topic 与消息格式 |
| 聊天机器人 / SDK | 消息、事件、会话范围 | 指定会话、频道或原会话回复 | 平台允许的额外操作 | 账号与平台凭据、会话映射、附件、速率限制 |
| CLI / 进程 | 可选持续输出或受控采集 | 可选标准输入协议 | 受控命令及参数 | 执行节点、可执行文件白名单、环境引用、工作目录、输出与退出码 |
| MCP Server | Agent 的调用、结果提交等协议请求 | 调用响应；客户端明确支持时才提供通知 | 发布工具、资源、提示词、任务访问 | 服务地址、开放范围、认证、协议与客户端兼容性 |
| 上游 MCP Client | 上游可发现内容与受支持通知 | 对上游服务调用 | 导入并审核的工具等 | 上游地址、认证、命名空间、能力变更审核 |

Webhook 是 HTTP Server 的接收模板，不应要求用户在“Webhook”与“HTTP 接收”之间重复创建同一入口。HTTP Client 可以发送消息，也可以作为工具执行器；HTTP 响应不自动变成第二条入口事件，除非显式配置。MQTT SUBSCRIBE/PUBLISH 共享 Broker 连接，但有独立端点、权限、错误和统计。MQTT 发布成功不是设备执行成功；QoS 2 也不代表业务只执行一次。

## 管理台配置流程

列表优先显示名称、协议、实际支持的接收/发送/调用标签、期望状态与观测状态、最近错误。创建流程为：

1. 选择类型：HTTP 接收、HTTP 请求、MQTT、聊天平台等。只展示已安装且可用的驱动；规划类型可在说明中列出，不做虚假可保存表单。
2. 配置连接：名称、服务器或运行节点、传输与凭据。共用字段只填一次。
3. 添加用途：接收消息、发送消息、提供操作。可多选，但只开放驱动支持的项。
4. 配置具体端点：每个入口或出口都有名称、消息说明、输入/输出 Schema、目标绑定、权限范围和版本。界面显示友好名称，技术 ID 放高级信息。
5. 校验与启用：区分配置检查、传输连通性检查和真实试发；真实试发显示具体 Topic/URL/收件人与内容。保存不暗中发布 MQTT 指令或调用写接口。

例如“家庭 MQTT”连接：

- 接收入口“温度状态”：`home/+/temperature`，QoS 1，JSON，retained 标记为状态快照。
- 发送出口“设备指令”：设备范围受约束的具体 Topic 模板，QoS 1，retain 默认关闭。
- 可调用操作“开启热水器”：参数为设备编号和目标状态，参数映射到已批准的发送出口，选择是否需要设备回执。

同一出口可由直接转发路由或 MCP 工具使用，统一执行权限检查、幂等、限流与审计；不为每种使用方式再配置一份 Broker 凭据。

## 路由配置与权限

来源选择器只列出已启用的接收入口；目标选择器只列出发送出口；MCP 能力选择器列出有明确调用契约的操作。用户不必先理解 Source/Sink/Executor 等内部接口。

直接转发：入口 → 筛选/映射 → 一个或多个出口。AI 处理：入口 → 授权任务收件箱 → Agent 经 MCP 领取/提交 → 原会话或指定出口。消息创建任务与 MCP 客户端主动触发调用是不同路径；不强迫所有消息经过 MCP。

入口的认证身份不是无限委托。连接可见范围、端点权限、路由授权、Agent 授权分别检查。Agent 的参数不能任意覆盖 HTTP URL、MQTT Topic、CLI 命令或回复收件人。需要动态目标时，只能从已批准范围或映射中选择。

MCP 当前多服务版本共用部署的认证配置，各有独立工具发布范围和版本。独立凭据、按服务 OAuth grants 及非默认服务的资源/提示词/收件箱配置列为后续扩展，不把“独立地址”宣传为独立认证域。

## 抽象与运行时

复用现有组合式能力，而非新增一个包含全部方法的万能 trait：

- `ConnectorFactory` 验证连接配置，构造可选 source/decoder/sink/tools/resource/prompt/lifecycle 能力。
- 入口定义描述订阅或监听绑定，运行时向 `EventIngress` 提交规范化事件和来源上下文。
- 出口定义描述发送绑定，运行时通过 `MessageSink` 与 Outbox 执行投递。
- 操作定义复用 `CapabilityDescriptor` 与 `ProtocolBinding`，由 `ToolExecutor` 执行。
- 连接底层会话可共享；端点分别有速率、并发、大小与排队预算，避免慢出口阻塞其他入口。

HTTP 回执在事件持久化后返回；不能用 200 声称 AI 已完成。MQTT 明确何时 ACK，重连后 retained/重复消息与实时新增区分。消息过大使用受控内容引用；排队有上限、TTL 与死信处理，超时或结果未知不能默认无条件重发。

停用入口表示停止接收或采集，不隐式删除既有任务；停用出口的积压任务进入明确阻塞/取消策略。删除被路由或 MCP 服务引用的端点应列出引用并阻止悬空配置，或在同一发布中解除引用。修改目标或 Schema 产生新版本，已接纳执行固定其版本。

## 落地顺序

1. MCP 多服务的真实 CRUD、独立工具目录和端点，并保持当前认证与审计。
2. 提炼连接/端点管理契约，接通已有 HTTP 接收与 HTTP 发送；来源、去向、试发都使用真实回执。
3. MQTT 订阅/发布驱动及共享会话监督，再接入消息路由编辑器。
4. 聊天/邮件/CLI 模板、更多 MCP 能力范围、独立服务认证与细粒度权限。

## 当前实现边界

连接持久化到 SQLite v16。消息连接的接收 ID 与发送 ID 分开，防止同一 MQTT 连接的不同方向被错误识别为内部循环；实际路由仍使用 `source_id` / `destination_id`。配置变更受工作区校验、CAS 版本、操作回执与 I/O 发布锁保护。删除引用与连接记录在同一事务中更新。有未分发入口消息或未解决投递时，拒绝更换协议配置或删除；名称、说明与启停可修改。尚未实现任意历史配置快照执行，因此不会将积压工作改投新 URL/Topic。

MQTT 共享 Broker、认证、TLS 配置；订阅使用独立持久会话，发布使用单次 clean session。在 PUBACK 丢失时不让客户端库后台自动重发。每个出口独立工作任务，共用全局发送并发预算；停用只暂停后续收发，已开始的外部副作用无法撤回。
