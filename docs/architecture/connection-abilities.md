# 连接能力：操作、资源状态与近期消息

2026-10-28。本文区分已实现的功能和后续接口设计。

## 职责边界

连接实例属于工作区，负责平台认证、接收、发送、能力发现和目标平台限制。连接声明操作（例如 QQ 发送文本、MQTT 发布）、资源状态和事件；路由持有指令触发、字段映射、可信来源范围和动作选择。指令不是平台操作，也不根据消息正文决定授权。

- **操作**：复用 `ConnectionActions` 和版本化 `ToolDefinition`，说明输入、作用与目标需求。QQ 现有操作只包含机器人信息和发文本；撤回、踢人等尚未接入，平台权限也不得假设。
- **指令**：复用 `ManagedRoute.command` 和 `RouteProcessor`。来源适配器验证来源与会话，路由匹配触发内容并在允许范围内调用操作或回复。当前动作触发和回复的适配器范围见 `docs/connection-routing.md`。
- **资源状态**：复用连接绑定的 MQTT 资源、状态分组和字段映射，记录时间、来源与新鲜度；实际收到的上报更新状态，发送命令本身不表示设备已执行。
- **近期消息**：面向按连接和会话的查询缓存；它不是接收、路由或投递的事实来源。事件存储和 Outbox 继续独立负责去重与可靠交付。

## 统一连接能力目录

`ConnectionCapabilityCatalog` 对每个连接描述三类能力：`operations`（操作及其版本、目标要求和副作用）、`resources`（资源、状态分组、有效期和状态查询操作）以及 `messages`（接收、发送和近期文本缓存支持）。目录描述能力，不授权执行；连接停用、平台权限、目标会话、工作区和 MCP 发布范围仍需分别检查。管理 API `GET /api/message-connections/{id}/capabilities` 返回目录和启用状态，不返回认证配置或密钥。

路由操作与 MQTT MCP 工具目录使用同一个操作目录生成器。MQTT 资源查询在当前实现中仍以操作方式供 MCP 使用；QQ 的发送操作需要显式绑定会话，目前可通过路由调用，尚未因为进入目录而自动发布到 MCP。Webhook 和 HTTP Client 没有自定义操作或资源时返回空列表，其接收/发送能力仍正常描述。

### 数据读取契约

`ConnectionStateReader` 按工作区、连接以及可选资源/分组返回类型化状态快照，字段保留值、来源、接收时间、设备时间及新鲜度。当前 SQLite/MQTT 实现支持此契约；MCP 状态查询工具和既有状态管理接口使用同一投影，按组查询不必读取其他分组。读取不会触发刷新或设备操作；需要主动刷新时仍由明确的设备操作处理。

`ConnectionMessageReader` 按工作区、连接、账号和会话读取有界近期消息。当前实现只支持 QQ，读取前核对当前连接启用状态、账号和群限制；缓存本身与上游事件持久存储保持独立。两种读取契约都是内部接口，**不构成授权**：管理台或 MCP 等上层必须先检查对应的主体、连接和会话权限。MCP 查询继续执行服务范围校验、审计和结果大小限制。

## 消息分类与处理

分类表达消息的用途，处理动作由路由和授权配置决定，二者分开。连接适配器提供来源、平台事件类型和可信元数据；路由可再结合 Topic、事件字段或明确配置的文本匹配规则分类。同一条上报既可能包含设备状态，也可能携带告警，因此允许一个事件匹配多项处理规则，不能依靠互斥枚举丢弃信息。

- **普通消息**：如群聊文本或 webhook 内容。可由路由过滤、转换并发送到其他连接；也可以按授权进入近期消息池。
- **状态消息**：例如 MQTT 设备定时上报。默认只更新匹配的资源状态；需要告警、归档或同步时，再显式配置转发。只有实际收到的上报能更新状态，发布控制指令并不证明设备状态已改变。
- **指令消息**：例如匹配 `/开灯` 的群聊消息，或已授权的设备控制请求。路由可调用本地操作后回复、转换并转发给其他连接（如 MQTT 设备命令），也可以仅记录或拒绝。文本匹配不是授权，必须核验来源、会话、发送者和目标操作权限；回执区分消息已发送、对端接受与设备确认。
- **其他事件**：例如告警、成员进入或连接生命周期事件，按来源能力和配置处理，不强行当作普通文本或指令。

当前已实现 MQTT 状态上报识别：入库事务使用连接配置的状态 Topic、身份条件和字段映射识别状态上报，状态更新和分类与事件入库一起提交。路由默认只处理普通消息和指令；需要转发状态上报时，在筛选条件中选择“状态上报”。无法匹配有效状态字段的消息不会被自动标记为状态上报。状态上报同时包含告警时，需要为相应路由显式选择状态上报。

路由可选择普通消息、状态上报和指令消息（多选为任意类型匹配）。指令类型由同一来源、相同来源范围中已启用的指令规则匹配确定；分类本身不授权执行。已识别状态的消息也可同时命中指令，普通消息表示未被识别为状态或指令的消息。类型在路由时依据当前启用规则计算，修改规则不会回填历史事件。每条路由至少选择一种类型；状态消息即使同时匹配指令，也只有选择了状态上报的路由才会处理。

告警类型与通用可配置分类规则尚未实现，不能将普通事件自动认定为告警。事件接收与去重先于状态更新和路由，可靠转发沿用既有队列、幂等和失败处理。近期消息池是查询用途，不决定消息是否转发。

## 近期消息池：本阶段实现

仅对已验签、通过连接过滤并成功持久化的 QQ 群及单聊文本建立进程内缓存。工作区、连接 ID、QQ 应用 ID、会话类型和 OpenID 全部参与隔离；同一上游事件去重后只记录一次。记录内容只包含消息 ID、发送者、接收时间和正文，不存储附件及链接元数据。超出 8 KiB 的正文跳过缓存，事件接收和路由不受影响。

缓存限制为每会话最多 100 条、每进程/数据库最多 2,000 条和约 2 MiB 内容预算、有效期 10 分钟；访问时即时淘汰，空闲数据每 30 秒清理一次，实际释放最多延后一个清理周期。触及容量限制时淘汰最旧消息。内存预算包含正文和标识的字节数及每条估算开销，不是进程 RSS 的硬上限。相同数据库在同一进程打开的 store 共享缓存；没有持有者时释放。重启后为空，不从持久化事件重建。QQ 连接删除、停用或配置改变时清空该连接的缓存。未支持消息池的来源不会产生记录。

内部查询端口需要确切的工作区、连接、应用账号和会话，以递减序列分页，页上限 50；返回 `history_complete=false`，不代表上游完整历史。序列只在当前缓存生命周期有效。只缓存机器人实际获授权并收到的事件，无法推断未收到的群消息。

**当前可通过显式授权的 MCP 内置工具查询 QQ 会话的近期文本。** 尚无单独的消息池管理台、可配置保留策略或通用消息适配器。

## 后续完善

- 为每个连接提供消息缓存启停及可配置的保留策略；当前缓存固定有界且仅支持 QQ 文本。
- 扩充 OAuth 授权、并发撤销和缓存重启的端到端覆盖，检查查询范围与审计。
- 增加日期范围、缓存丢失和截断信息，以及更多连接适配器；近期消息池不是完整历史或主动唤醒机制。
- 扩展到更多连接的状态和告警分类，并在路由界面进一步展示各类消息的处理动作。
