# 并发与内存设计

2026-10-24，v0.4 性能补充。最新状态见[P1 内容存储、调度与契约](p1-storage.md)。优先限制在途数据、隔离慢任务、减少大载荷的重复构造，再根据测量调整并发。吞吐优化必须保留授权、幂等、事务和结果未知的语义。

P1 进一步增加关键 SQL 最多连续 4 次的公平优先调度、独立文件配额及按实际访问路径设计的部分/复合索引；旧阶段微基准保留为历史测量，不代表 P1 的吞吐数据。

## 已落地的第一批优化

| 路径 | 当前实现 | 边界 |
|---|---|---|
| HTTP 接收 | 每个 Pipeline 最多 64 个已获准的正文读取/解析/持久化请求；满载在读取正文前返回 503 和 Retry-After | 单请求仍为 64 KiB、读取超时 5 秒；不限制整个服务器的连接数；SDK 直接调用需自行限制生产速率 |
| SQLite | 每个共享 SqliteStore 普通操作最多 64 个，关键完成操作另有 8 个接纳名额，包含执行与等待；超限立即返回 RateLimited | Tokio Mutex 异步等待连接，最多等待 5 秒；取得连接后才 spawn_blocking；每个 Store 最多一个 SQL 阻塞任务在途 |
| SQL 取消 | 连接 guard 和容量 permit 一起移入阻塞闭包 | 等待阶段取消可回收容量；SQL 已开始则直到结束才释放，不能把调用方取消当作事务回滚 |
| 后台流水线 | 路由与各目标独立调度；每目标串行，每批最多 100 条；全局有界并发 | 慢目标不拖住其他有可用名额的目标；全目标严格顺序可配置，尚无会话分区；正常停止排空在途发送 |
| HTTP 输出 | 借用 ContentPart 切片和 JSON/Text 内容直接序列化，取消临时 Vec<Value> 和第二棵 JSON 树 | 输出仍需要一个序列化字节缓冲，属于减少拷贝，不是端到端零拷贝；v1 字段语义不变，JSON 对象键顺序可能变化 |
| 入口缓冲 | JSON 解码成功后提前释放原始请求 Bytes | 解码后的 owned DTO 继续用于持久化，不同时持有不再需要的原始正文 |

数据库 admission 的边界是一个 Store 及其 clones；对同一数据库重新 open 会产生独立门限。当前 Pipeline 共享一个 Store，跨进程仍依靠 SQLite 事务与 busy timeout。连接等待超时发生在 SQL 提交之前；spawn_blocking 后不再用外层 timeout 截断提交。最初这批优化没有改变数据库格式；后续容量保护已升级至 schema v2，并直接使用 rustix 探测 Unix 磁盘空间，见[积压容量与异常恢复](backpressure.md)。

数据库 debug span 增加 queue_wait_us 与 execution_us，前者从接纳到取得连接，后者是闭包实际执行时间，不含 Tokio blocking pool 调度等待。它们是诊断样本，不是持久化指标直方图。

## 模块并发与数据所有权

以下是后续实现约束；共享缓冲、分片调度、缓存与流式内容尚未整体落地。

| 模块 | 并发边界 | 内存与数据策略 |
|---|---|---|
| 配置控制面 | 每个对象发布使用 expected_revision CAS | 已发布配置用 Arc<Snapshot> 共享；短锁取出快照后释放，校验/网络操作在锁外 |
| 能力目录与发布 | 发现任务按连接单飞，目录读取可并行 | 编译后的 Schema 按 revision/dialect 缓存，限制条目数与字节数；发现结果不复制给每个请求 |
| 身份权限与审批 | 授权查询可并行，审批消费 CAS | 缓存键含主体、客户端、工作区和授权 epoch；缓存失效不能为了命中率放宽 |
| 凭据管理 | 同绑定刷新单飞，版本提交 CAS | 秘密只短期持有，不能放入通用 Arc 配置快照、日志或长期缓存 |
| 连接器运行 | 按连接/来源分区限制实例与重连 | 共享连接池和不可变配置；重连退避带抖动，缓冲按条数和字节数双限制 |
| 事件接收与来源 | 上游确认顺序受分区契约约束 | 单消费者移动 owned payload；共享原始字节用 Bytes/Arc<[u8]>；大对象改 ContentRef |
| 路由 | 独立事件可有界并行，需要顺序的事件按 ordering_key 串行 | 同一不可变事件借用或 Arc 共享给多个规划器；扇出上限显式限制，避免复制完整 JSON 树 |
| 投递 | 不同目标可并行；同会话默认单通道，平台配额再限速 | 队列保存 ID/内容引用，只有获得执行许可后才加载正文；复用 HTTP Client |
| 工具与 Runner | 按节点、工具和副作用序列限制并行 | stdout/stderr 分块消费并设总量上限；产物流式落盘；不让等待任务提前占用执行进程 |
| Agent 任务 | 按 Agent/工作区领取配额；同会话按版本处理 | 输入保存消息引用与固定上下文范围；限制上下文条数、字节数，避免每个 Job 复制历史 |
| 会话与附件 | 消息版本 CAS，分块上传和下载各有限额 | 流式 ContentStore、摘要增量计算；不能为便于传参把附件转 base64 塞进每份事件 |
| MCP 与桥接 | 每会话限制在途请求，控制消息保留处理空间 | 共享只读发布快照，按页返回目录/资源；上游响应/嵌入内容有大小上限 |
| 审计与观测 | 关键审计随业务事务，异步导出有界批次 | 热路径只记 ID/阶段/错误码；导出批次受条数和字节双限，不堆积正文 |
| 存储与运维 | 单机写入串行；读池/批提交须经负载验证后引入 | 队列先接纳再加载大对象；备份/清理限速；不以放宽 FULL/提交确认换吞吐 |
| 管理接口与 SDK | 分页查询、版本 CAS、有限客户端重试 | 读模型投影需要的列，限制页面/返回字节；SDK 保留原幂等键，不无限缓冲重试 |

## 共享类型与端口原则

单一消费者使用所有权移动；调用期间用 &T、&[u8] 或 &str。跨异步任务、跨消费者且不可变的内容才使用 Arc<T> 或共享字节。小 ID、枚举和少量上下文直接复制，避免原子引用计数与额外堆分配。领域层不为减少一个小对象 clone 引入复杂生命周期。

借用生命周期不超过拥有者；需要 spawn 的任务必须移动 owned 数据或 Arc，不得通过泄漏内存伪造 static。trait 对象边界继续使用已有 PortFuture；只有 profiling 证明每次 boxed future 分配重要时，才为内部热点增加具体类型/泛型路径。

Bytes 的切片可能保留整个大 backing buffer：长期保存小片段时可以主动复制，以便释放大缓冲。Arc<Value> 解决共享，不解决 JSON 解析、持久化编码或网络输出；JSON 原文保留、RawValue/延迟解码只适用于无需检查字段的路径。需要权限校验、筛选和转换时仍然解析，并设置深度和大小上限。

P1 通过 ContentRef 共享大内容，流式读写文件；inline EventPayload/Message 仍为 owned 类型。SQLite schema v4 的事件/投递采用 storage_version=2 外壳并兼容旧记录，存储版本与协议版本分别演进。

## 背压与调度契约

在途内存预算应按“各队列容量 × 每项实际保留字节 + 执行中正文 + 解析对象 + 缓存 + HTTP/TLS 缓冲”估算。64 × 64 KiB 仅约束 HTTP 原始正文的一个部分，不能当作进程总内存上限；JSON 对象、字符串、任务栈和数据库页缓存另计。

来源运行、路由、投递、Agent 通知、工具执行与审计导出分别有预算。嵌套限额按固定顺序取得，不能持有数据库锁等待网络配额。先取得运行许可再领取有时效的业务租约，避免租约在本地等待时到期。当前 SQLite 已为发送/完成状态等关键操作保留 8 个接纳名额；连接仍串行，后续公平调度需进一步控制等待。

支持重放的来源在未持久化时拒收/暂停，由上游使用原键重试；不支持重放的来源明确丢失窗口。已返回持久化成功的任务继续保存在数据库，内存队列只作唤醒提示。不得用无界 channel、每消息无限 spawn 或全量 join_all 规避背压。

独立调度消除了慢 HTTP 对路由的串行阻塞；后续容量阶段已实现 RoutingTask 的退避和 blocked 隔离，101 条永久失败任务不会占据后续扫描窗口。同会话 ordering_key、分布式路由租约、按租户/目标公平调度仍待实现。

## 测量与验收

回归测试覆盖：数据库接纳满载、等待者取消释放容量、执行者取消仍提交、HTTP 入口满载恢复、慢目标不阻塞路由、停机等待当前发送、v1 输出兼容，以及既有幂等/事务/租约测试。

手工序列化测量使用 release 构建，60 KiB 字符串加嵌套 JSON 与文本，每组 2000 次、4 轮交替顺序。两条路径都在计时前创建相同输入，计时包含编码和输入释放，不包含网络/数据库。比较旧 Value 构造路径与新借用 DTO；输出内容相同，耗时不作为 CI 硬阈值。

2026-10-24 本机 macOS arm64、rustc 1.98.1 的一次运行：旧路径各轮 50.107 / 45.726 / 45.063 / 45.265 ms，新路径 35.342 / 35.205 / 35.137 / 34.775 ms；每组输出 123,280,000 字节。中位数 45.50 → 35.17 ms，编码耗时减少约 23%。未采集 allocator 分配计数或 RSS，不能据此给出内存降低比例。该次基线为 43 项后端回归测试通过，手工测量另行通过；容量与异常恢复补充后为 52 项测试通过、1 项手工测量默认忽略，Clippy 全目标检查通过。未重新运行编码微基准。

```sh
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --release -p synquay-server --lib measure_http_encoding -- --ignored --nocapture
```

下一轮端到端容量测试固定机器、release 构建、数据库大小、payload 分布、扇出和模拟目标延迟。采集完成吞吐、接收/排队/端到端 p50/p95/p99、RSS 峰值、分配量、数据库锁等待、拒收比例与最老积压年龄；负载发生器也必须有界。吞吐统计包括失败、拒收和 drain 时间，不能只计算快速成功请求。当前微基准不代表生产吞吐或内存节省比例。
